# Design: Wiki Page Staleness Detection

**Date:** 2026-05-28  
**Status:** Approved  
**Scope:** Add `obsidian_wiki_stale_pages` to detect wiki pages that have been superseded by new vault content  

---

## Problem

Wiki pages generated by `obsidian_write_wiki_page` become stale over time: related notes are updated, new source notes appear, but the wiki page is never regenerated. There is no tool to surface which pages need refreshing. The tool should return a ranked list of stale pages so a calling LLM can decide which ones to regenerate.

---

## Architecture Overview

### New Tool (1)

| Tool | Responsibility |
|---|---|
| `obsidian_wiki_stale_pages` | Scan `wiki/` folder, apply two staleness signals, return ranked stale page list |

### New Internal Helpers (helpers.py)

| Helper | Responsibility |
|---|---|
| `_stale_wiki_pages_scan(vault, wiki_folder, min_age_days, since_days, max_new_notes, top_n)` | Core scan logic; returns `list[dict]` |
| `_parse_created_ts(props, path)` | Parse `created` frontmatter field → Unix timestamp; fallback to `st_mtime` |
| `_title_keywords(title)` | Tokenise page title → keyword list for content matching |

### Data Flow

```
obsidian_wiki_stale_pages(vault_path, wiki_folder, min_age_days, since_days, ...)
    │
    ├── Scan wiki_folder/ → candidate pages (created <= now - min_age_days)
    │
    ├── For each candidate:
    │     ├── Signal 1: related frontmatter links with st_mtime in (page_created, now-since_days]
    │     └── Signal 2: vault .md files with st_mtime in (page_created, now-since_days]
    │                   AND content contains title keywords
    │
    └── Return stalePages list (sorted by newNeighborCount desc, capped at top_n)
```

### No New Dependencies

All operations reuse existing helpers: `_vault()`, `_safe_path()`, `_read_text()`, `_write_text()`, `_split_frontmatter()`, `_iter_files()`, `_rel()`. No new Python packages required.

## Section 1: Signature and Parameter Semantics

```python
@tool()
def obsidian_wiki_stale_pages(
    vault_path: str = "",
    wiki_folder: str = "wiki",
    min_age_days: int = 7,
    since_days: int = 7,
    max_new_notes: int = 5,
    top_n: int = 50,
) -> dict[str, Any]:
```

| Parameter | Semantics |
|---|---|
| `wiki_folder` | Folder containing wiki pages; default `"wiki"` |
| `min_age_days` | Only check pages whose `created` is at least this many days ago (filters out freshly generated pages) |
| `since_days` | Only count changes that occurred within the last N days (time window applied to neighbour/note modifications) |
| `max_new_notes` | Maximum new-notes entries returned per stale page (prevents output explosion) |
| `top_n` | Maximum number of stale pages returned |

**`created` timestamp resolution:**
1. Parse `frontmatter["created"]` as ISO UTC string (written by `obsidian_write_wiki_page`)
2. Fallback: `path.stat().st_birthtime` (Windows/macOS) → `path.stat().st_mtime` if unavailable

---

## Section 2: Staleness Algorithm

```
now           = time.time()
cutoff_change = now - since_days × 86400     # changes must be newer than this
page_age_cutoff = now - min_age_days × 86400 # page must be older than this

For each .md in wiki_folder/:
    page_created = _parse_created_ts(props, path)
    if page_created > page_age_cutoff:
        skip  # page too new

    Signal 1 — related modified:
        for r in frontmatter.get("related", []):
            rel_path = resolve(r)
            if rel_path.exists() and page_created < rel_path.st_mtime and rel_path.st_mtime >= cutoff_change:
                → modifiedRelated.append(r)

    Signal 2 — new vault notes:
        keywords = _title_keywords(title)
        for f in _iter_files(vault) where f not in wiki_folder/:
            if page_created < f.st_mtime and f.st_mtime >= cutoff_change:
                content = _read_text(f).lower()
                if any(kw in content for kw in keywords):
                    → newNotes.append({path, mtimeDays})

    if modifiedRelated or newNotes:
        → add to stalePages
```

**`_title_keywords` tokenisation:** split on whitespace and CJK-aware punctuation (`[\s/\-_,;:。，、　]+`), keep tokens with `len >= 2` (supports Chinese single-character words via length-1 override for CJK codepoints).

**Sort order:** `stalePages` sorted descending by `newNeighborCount` (= `len(modifiedRelated) + len(newNotes)`), then truncated to `top_n`.

## Section 3: Return Structure

```json
{
  "stalePages": [
    {
      "path": "wiki/reactor_design.md",
      "title": "Reactor Design",
      "daysSinceCreated": 14,
      "reasons": ["related_modified", "new_notes"],
      "modifiedRelated": ["entities/agitator.md"],
      "newNotes": [
        {"path": "sources/new_paper.md", "mtimeDays": 2}
      ],
      "newNeighborCount": 3
    }
  ],
  "checkedCount": 12,
  "staleCount": 3,
  "wikiFolder": "wiki",
  "minAgeDays": 7,
  "sinceDays": 7
}
```

| Field | Description |
|---|---|
| `reasons` | Subset of `["related_modified", "new_notes"]`; which signals fired |
| `modifiedRelated` | Vault-relative paths of modified related notes |
| `newNotes` | Up to `max_new_notes` new matching notes, each with `path` and `mtimeDays` (integer days since modification) |
| `newNeighborCount` | `len(modifiedRelated) + len(newNotes)` — priority signal for calling LLM |
| `checkedCount` | Total wiki pages examined (age-filtered candidates) |

---

## Section 4: Error Handling

| Condition | Behaviour |
|---|---|
| `wiki_folder` does not exist | Return `stalePages: []`, `checkedCount: 0`, no error raised |
| `related` field missing or not a list | Skip Signal 1 for that page; no crash |
| Related path escapes vault or does not exist | Skip that entry silently |
| Page has no `created` field | Fallback to `st_mtime`; page still checked |
| Unreadable `.md` file (encoding error) | Skip that file; continue scan |

## Section 5: Testing Strategy

6 unit tests appended to `tests/test_obsidian_vault_mcp.py`, following the existing `tmp_path` + `write_note` + `os.utime` pattern.

| Test | Coverage |
|---|---|
| `test_stale_pages_related_modified` | `related` note mtime > created and within since_days → Signal 1 fires |
| `test_stale_pages_new_notes_keyword` | New vault note contains title keyword → Signal 2 fires |
| `test_stale_pages_min_age_filters_new_pages` | Page created < min_age_days ago → not in results |
| `test_stale_pages_since_days_window` | Neighbour modified outside since_days window → not counted |
| `test_stale_pages_no_related_field` | `related` missing → Signal 1 skipped, no crash |
| `test_stale_pages_top_n_limit` | More stale pages than top_n → result capped |

**Post-unit-test real-world test:**
1. Run `obsidian_wiki_stale_pages(vault_path="<real vault>", since_days=30, min_age_days=3)` against the live vault
2. Verify `stalePages` list matches expected pages
3. Confirm no errors or unexpected output
4. Clean up any temporary test files
